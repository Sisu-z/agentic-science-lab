# 给后续 Agent 的重点提醒

本页由本项目编写，不是教程原文，也不是赛事方新增规则。先读 [原文副本](original.txt)；有疑问返回 [原始页面](https://dptechnology.feishu.cn/docx/MJwXd4ek3oFGONxSHuwcl83LnUS)及当前题目说明核对。

## 必须注意的原文要求

1. **真实完成科学任务。** 教程前部及第 11 节强调：不能搜现成答案、猜答案、伪造计算或针对评分器漏洞硬编码。第 11 节允许的公开数据和论文交叉核验，不等于允许检索特定题目的现成解；具体联网边界要按题目确认。
2. **不读取隐藏评测材料。** 第 6 节明确列出 hidden tests、checker 和官方 solution。不要把“可以运行允许的验证命令”理解成“可以打开评测器源码找答案”。
3. **原生轨迹要真实。** 前部和第 8 节要求可审计的过程，并如实填写实际模型及 harness。没有真实 trace 时不要补造。教程提供先交 outputs 的路径，但实际提交仍须满足当前题目及当前 CLI 的要求。
4. **结果分与轨迹分要分开看。** “关于评分”说明两种评分用途不同，实时轨迹分可能调整；这不表示可以省略过程证据，也不能把本地通过宣称为平台通过。
5. **先弄清输出合同。** 第 3、4、6 节要求先读题面和元数据，确认输入、文件名、格式、资源、联网与依赖限制。先做 baseline 的建议不等于最终可以遗漏计分子目标。
6. **保留复现材料并避免泄密。** 第 5–7 节分别安排结果、脚本、轨迹、日志、远程作业记录和方法摘要；不把凭据、缓存或无关大文件装进提交包，不打印全部环境变量。原始日志与本项目公开仓库的脱敏副本分开保存。
7. **提交与排错闭环。** 第 8、10–13 节要求保存提交回执和 attempt ID，查询实际评测状态；失败先定位层次，低分先检查路径、格式、单位、排序、随机性和缺失值，而不是盲目重复提交。
8. **资源预算是建议，不是题目时限。** 第 11 节的 15 分钟、60 分钟、半天以上是分阶段投入建议；具体题目的时间限制优先。远程资源是否可用、是否收费、是否得到授权需要另行核实。
