# 多 Agent 协作

仓库由维护者持有。不同 Agent 使用维护者授权的本地工具或各自的授权环境访问，无需为每个子 Agent 单独注册 GitHub 账号。

## 一项工作，一个分支

使用 `task/<short-name>`、`skill/<name>` 或 `module/<name>` 分支。并行工作使用独立 worktree 或 clone，公共文件由整合者协调。

每项工作只需明确目标、负责目录、交付物和验收标准。Agent 在自己的分支上提交，通过 Pull Request 交接；负责整合的 Agent 或维护者检查证据、处理冲突并合并。

## 最小交接

- 完成了什么，关联哪个题目或问题。
- 修改了哪些文件，如何运行。
- 实际做过哪些验证，结果是什么。
- 未完成事项、失败尝试、已知限制。

## 从单题到资产

单题实现 → 实际验证 → 复盘 → 确认复用价值 → 提炼 Skill/模块 → 用新的输入验证。

平台生成的 Skill 可以成为候选素材，但生成成功或原题高分不证明它在其他题目上有效。保留来源 attempt ID，并对适用条件重新验证。
