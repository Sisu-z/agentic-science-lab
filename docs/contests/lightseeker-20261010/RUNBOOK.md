# 24 小时指挥与交付流程

本届赛时已于北京时间 2026-10-11 20:00 结束；下表保留为执行期计划，不触发新作答或提交。后续组织改进见 [协作复盘](RETROSPECTIVE.md)，既有接收与待终态项只读原 Issue。

本页时间安排和止损点为团队设计，非官方评分规定。总监按题目规模、首轮实际耗时和用户状态调整；不要求维护者连续熬夜。

| 23:00–次日 08:00 | 只推进有明确收益依据的实验；保留最佳已验证版本、保存检查点；长任务先核资源授权与可恢复性 |
| 08:00–12:00 | 总监按实际指标收敛改进；按独立题的证据和审查容量推进，不同时扩张不确定方向；必要时换路线并保留失败证据 |
| 12:00–15:00 | 独立验证、干净环境重放、轨迹与成果关联检查；完成或更新有效提交，查询回执 |
| 15:00–18:00 | 进入交付保护窗口，优先修验收/打包/复现问题；只有证据充分且可回退的增量继续 |

首个可运行版本只说明交付路径有基础；必须另有与题目目标相关的正确性检查。不同主攻题之间、主攻和必做之间均可在依赖明确时并行，但审查、同一账号和提交动作保持串行。

下次有硬截止的项目，启动即核必做与资格/身份门槛，预留必要本人操作和接收余量。简单且已授权的上传、填表和回执核验由总监直接办理，不为此增建聊天；门槛有明确暂停时不得擅自代办。

只要首个版本满足本题基本验收并获该题提交授权，就尽早提交以验证正式链路和取得反馈；不因上表的次日检查时段而等待。后续继续改进独立版本，保持可回退。

## 每题六道验收

1. **合同**：正式题稳定 ID、输入/输出、计分关系、资源限制、允许联网/依赖与时限均已写到任务。确认必做、可选、前置及分项门槛，不把练习当正式分。
2. **有效基线**：真实执行产生合法产物，并有公开小例、残差/守恒、留出验证、单元约束或独立实现等相适应的检查。文档及格式不替代有效结果。
3. **改进证据**：每轮记录假设、代码/输入版本、命令/工具、结果及取舍；在独立版本改进，保留最佳已验证版本。失败没有新证据就定位原因。
4. **可重放交付**：按题面验证确切目标文件/入口；从干净目录重放，检查环境、依赖、退出状态、格式和关键指标；不要只跑开发目录里的旧输出。
5. **真实轨迹**：从实际作答开始保存原生记录，覆盖获取输入、实现、执行、验证、失败与修正；关联产物校验值。原生与结构化轨迹的转换按当前工具验证，不补造事件、不填充思考。多成员贡献必须可追溯到实际记录。
6. **平台回执**：唯一操作者提交，保存 attempt ID、包指纹、提交时间和服务器响应；查询当前状态、任务分、轨迹情况与最终性。`queued/running/scoring` 不是通过，显示 0 也需看是否终态。

上一题暴露了入口不落目标文件、全局 CLI 轨迹与本地副本不同、只附部分过程以及旧回执滞后等风险。这些用于设置验收，不能拿旧题修复包当本届可用答案。

## 工具操作形状

以下仅是已有 CLI 的操作参考；执行者先读当前 `--help`，按题目替换参数，不运行占位命令。原始证据和凭据在仓库外。

```sh
playground auth status
playground doctor
playground task list --limit 20 --json
playground task download --challenge-id CHALLENGE_ID --out task
playground trace validate --trace NATIVE_TRACE
playground submit --help
# 使用已确认的新版，先本地预检，不上传：
playground submit --challenge-id CHALLENGE_ID --outputs outputs --trace NATIVE_TRACE --raw-messages NATIVE_TRACE --model ACTUAL_MODEL --harness ACTUAL_HARNESS --dry-run
# 核对预检包，再在完成验收且获该题提交授权后移除 --dry-run 正式提交：
playground submit --challenge-id CHALLENGE_ID --outputs outputs --trace NATIVE_TRACE --raw-messages NATIVE_TRACE --model ACTUAL_MODEL --harness ACTUAL_HARNESS
playground status --attempt-id ATTEMPT_ID --bundle
```

现代 Codex JSONL 的本地样本实测需同时显式给 `--trace` 与 `--raw-messages`，以保留完整创建接口轨迹。dry-run 后检查包内真正的 `raw_messages.jsonl`、相应 native_trace 原件、结构化事件和 manifest，核字节关联与可用事件；样本通过不等于完整作答证据通过。当前工具不自动收集 Codex 子日志。

现有下载包可能含禁读路径；不能为了列目录或验收而展开 hidden tests/checker/solution 内容。只使用允许的公开题面、输入和验证入口。旧题脚本含硬编码，不直接套用。

## 卡点处理与维护者界面

总监先定位是规则、账号、输入、方法、实现、资源、打包、轨迹还是评分问题；派一个负责人给下一项可区分检查和时间边界，避免多人重复猜测。涉及付费、安装、身份材料上传和不可替代的现实操作，合成一个具体、可审阅请求；其他授权内工作继续。

每次汇报只需：当前阶段；已验证成果；最大卡点；下一步与检查时间；是否需要维护者操作。维护者可以只说“核对进展／继续／卡住了／换方向”，总监直接读任务与证据，调度后续。

总监在当前任务执行中持续检查进展、组织下一步和验收，按有意义变化汇报。不设置后台轮询或自动唤醒；中断后通过共同任务和证据接手。
