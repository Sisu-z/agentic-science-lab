# 全栈开发项目｜招募赛成员入口

**本届赛时已结束。** 不因读取历史分配而重新开题、返修或提交；赛后只执行明确的复核/整理任务。可复用组织改进见 [协作复盘](RETROSPECTIVE.md)，实时终态只读原 Issue。

本项目用于追光者计划招募赛，主攻科研 Agent 全栈开发工程师／实习生。比赛时间：北京时间 2026-10-10 20:00 至 10-11 20:00。当前总监对话负责统筹、引导、协调、审查与汇总；具体题目由维护者创建或明确授权总监创建的可见对话完成。不得自行用内部子 Agent 替代这些对话；创建范围按维护者直接授权，不设置后台轮询。

2026-10-11 维护者直接授权离开期间由总监在当前聊天执行中托管、监督正常提交和按实质反馈返修，并继续安排后续可见单题任务。各题仍只认原 Issue 的唯一当前运行和提交操作者。直接创建接口尚不支持 ChatGPT 项目下的本地新建；可见本地对话可以通过本仓库与共同材料协作，不宣称其界面项目标签已归属“全栈开发”。

## 新对话开始时做什么

1. 读取仓库 [AGENTS.md](../../../AGENTS.md)、[比赛说明与规则](README.md)及[协作约定](TEAM.md)。
2. 从[唯一任务源 Issues](https://github.com/Sisu-z/agentic-science-lab/issues)找到用户指定题目或当前分配，读取头部与最新评论；确认稳定题号、目标、当前修订、本人职责、run_id、产物及验收。没有题目分配时，可登记承接意向，不能匿名开工或沿用旧运行。
3. 阅读[共享平台操作手册](PLATFORM.md)，沿用既有教程副本、账号/环境和已核操作；再查[共享经验](EXPERIENCES.md)及关联题的 Issue，先复用已验证的规则/工具经验；每条经验都须核适用环境和未覆盖项，不将别题答案当自己的证据。
4. 读取 Issue 的材料逻辑键，仅加载自己需要的正式合同和受控材料。同一台 Mac 可由本机工作根 AGENTS.md 定位 materials.json；其他环境须先报告访问缺口，不能声称 GitHub 指针就是可读附件，也不让用户转述技术报告。
5. 向本题 Issue 回填“对话标识或可访问链接、准备承担的职责、依据修订、环境/材料可访问性”。总监串行登记唯一当前运行后开始。用户在本对话明确指定题目和职责可作为分配依据，由有写能力的总监补录，成员不必等待额外重复确认。

## 一道题一个或两个对话

- 一个对话：负责主要实现和自检。
- 两个对话：主实现对话产出候选，另一个负责独立核查、特定调查或交接；在同一个 Issue 写清各自范围，不竞争写同一文件。
- 不同题：各自 Issue、独立目录、输入/输出和真实记录，可并行。
- 总监：查看 Issues、PR 和证据，处理共同卡点及跨题关联，不要求维护者搬运成员报告。

## 什么时候、回填什么

开始、有效候选、阻塞、交接、提交回执和接受时回填；无需逐条工具调用刷评论。使用 [任务与结果模板](TASK_TEMPLATE.md)：任务/修订/run_id、确切版本、实际验证与结果、未覆盖项、阻塞及下一步。中断前留下可接手检查点；独立复核写清被审版本。

题目过程留原 Issue；允许公开的改动通过 PR 审查并合入 main；可跨题复用的经验在本目录 EXPERIENCES.md 建索引，正文优先留原 Issue/已有说明。关联题需采取行动时，在其 Issue 留链接与影响，由总监协调；不复制一套任务表。

## 材料边界

本仓库公开，只存可公开的规则、组织约定、脱敏进度与经验。正式题面、数据、解题源码、答案、简历及原始轨迹留受控位置。各对话保存自身真实执行记录，不能假定项目内聊天或子日志自动合并。正式提交由总监指定唯一操作者，并遵守该题授权；安装、付费、个人材料处理按已有明确授权执行。
